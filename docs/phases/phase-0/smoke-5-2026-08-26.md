## Invariant-compliance audit (same wave)

Run alongside the walk; every claim below was cite-checked against the tree, and all four were corrected in the same change as F2/F3.

1. **CLAUDE.md asserted a mechanism that does not exist** — "repository functions that write also fire the commit broadcast (ADR-3)", stated as a current rule. `grep -rn broadcast crates/` finds exactly one hit, a comment in `crates/store/src/lib.rs:5` correctly phrased as future. `phase.md:49` had already recorded the correction (walk-4 F6) and CLAUDE.md had not followed — a same-commit-update rule drifting against its own rule 5.
2. **INV-DEPLOY-1's sandbox read as shipped.** The 2026-08-23 addendum said "Surge-spawned processes are network-sandboxed" in the present tense. There is no Seatbelt profile, no `sandbox-exec`, no network namespace anywhere; `crates/compiler/src/capability.rs` returns one hardcoded egress string for every project and its own comment admits the allowlist is Phase 2. design §23-Nineteen says *resolved*, which is a decision, not a ship. Reworded to the decision it is, with a dated amendment — and the same treatment applied to INV-AUTH-6's adjacent "auto-appended to the worker sandbox allowlist" clause, which depends on the same unbuilt sandbox.
3. **INV-DATA-1 and INV-DATA-7 contradicted each other.** INV-DATA-1 named a closed list of exactly four repo writes; `crates/compiler/src/write.rs::upsert_gitignore_block` creates and rewrites `.gitignore` at the repo root on every compile — a fifth kind — and INV-DATA-7 *requires* it to. So the shipped compiler violated the closed list on every compile, by doing what another invariant demanded. **Decision: enumerate.** `.gitignore` becomes the fifth item, scoped to the surge-managed block between its markers with every surrounding line preserved byte-for-byte. The alternative — softening the rule to "four kinds plus whatever INV-DATA-7 needs" — would have stopped the list being closed, and closedness is the entire content of the rule. Propagated to `invariants.md`, `spec.md`, `architecture.md` (prose + container diagram), `CLAUDE.md`, `design.md` §01 and the `crates/compiler/src/write.rs` header. One stale restatement remains: `crates/store/src/work_orders.rs:1` ("one of the four repo writes"), left untouched because `crates/store/src/**` was owned by another task this wave.
4. **`code-map.md` listed planned components indistinguishably from shipped ones** — the `ui` row's "React Flow canvas" (no `@xyflow/react` in `ui/package.json`) and the `server` row's "tracker mirror, SSE bridge" (no such module in `crates/server/src/`). The header said paths were "planned", which covered the *paths* and not the *contents*. Every row now annotates its contents **(now)** / **(P1)** / **(P2)** / **(P3)**. `crates/domain/bindings/` — ts-rs's default export directory, a gitignored byproduct superseded by `ui/src/generated/` and read by nothing — was undocumented and is now named, alongside the other two generated-and-ignored directories and the guard each one has.
